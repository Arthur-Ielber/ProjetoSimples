================================================================================
                    TABELAS DO SISTEMA DE RESTAURANTE
================================================================================

Este documento lista todas as tabelas utilizadas no banco de dados MySQL
do sistema de gestão de restaurante.

================================================================================
1. CONFIGURACOES
================================================================================
Descrição: Armazena as configurações gerais do restaurante (telefone, email,
           horário, história, mapa).

Campos:
  - id (VARCHAR(36)) - Identificador único (UUID)
  - telefone (VARCHAR(50)) - Telefone de contato
  - email (VARCHAR(255)) - Email de contato
  - horario (TEXT) - Horário de funcionamento
  - historia (TEXT) - História do restaurante
  - mapa_url (TEXT) - URL do Google Maps (iframe)
  - created_at (TIMESTAMP) - Data de criação
  - updated_at (TIMESTAMP) - Data de última atualização

Relacionamentos: Nenhum

================================================================================
2. MENU_SECOES
================================================================================
Descrição: Armazena as seções do menu (Entradas, Pratos Principais, 
           Sobremesas, etc.).

Campos:
  - id (VARCHAR(36)) - Identificador único (UUID)
  - nome (VARCHAR(255)) - Nome da seção (único)
  - ordem (INT) - Ordem de exibição
  - created_at (TIMESTAMP) - Data de criação
  - updated_at (TIMESTAMP) - Data de última atualização

Relacionamentos: Nenhum

================================================================================
3. EMENTA
================================================================================
Descrição: Armazena os itens do menu (pratos, bebidas, etc.).

Campos:
  - id (VARCHAR(36)) - Identificador único (UUID)
  - nome (VARCHAR(255)) - Nome do prato
  - descricao (TEXT) - Descrição do prato
  - preco (DECIMAL(10,2)) - Preço do prato
  - secao (VARCHAR(255)) - Seção do menu
  - destaque (TINYINT(1)) - Se é destaque (0 ou 1)
  - ativo (TINYINT(1)) - Se está ativo (0 ou 1)
  - imagem_url (TEXT) - URL da imagem do prato
  - created_at (TIMESTAMP) - Data de criação
  - updated_at (TIMESTAMP) - Data de última atualização

Índices:
  - idx_secao - Índice na coluna secao
  - idx_ativo - Índice na coluna ativo

Relacionamentos: Nenhum (secao é texto, não FK)

================================================================================
4. MESAS
================================================================================
Descrição: Armazena as mesas do restaurante.

Campos:
  - id (VARCHAR(36)) - Identificador único (UUID)
  - numero (VARCHAR(50)) - Número da mesa (único)
  - capacidade (INT) - Capacidade de pessoas
  - ativa (TINYINT(1)) - Se está ativa (0 ou 1)
  - created_at (TIMESTAMP) - Data de criação
  - updated_at (TIMESTAMP) - Data de última atualização

Índices:
  - idx_ativa - Índice na coluna ativa

Relacionamentos:
  - Referenciada por: reservas.mesa_id, pedidos.mesa_id

================================================================================
5. RESERVAS
================================================================================
Descrição: Armazena as reservas de clientes.

Campos:
  - id (VARCHAR(36)) - Identificador único (UUID)
  - nome (VARCHAR(255)) - Nome do cliente
  - apelido (VARCHAR(255)) - Apelido do cliente
  - telefone (VARCHAR(50)) - Telefone do cliente
  - email (VARCHAR(255)) - Email do cliente
  - data_reserva (DATE) - Data da reserva
  - hora_reserva (TIME) - Hora da reserva
  - numero_pessoas (INT) - Número de pessoas (1 a 20)
  - estado (ENUM) - Estado: 'pendente', 'confirmado', 'cancelado', 'finalizado'
  - mesa_id (VARCHAR(36)) - ID da mesa (pode ser NULL)
  - token_confirmacao (VARCHAR(255)) - Token para confirmação (único)
  - created_at (TIMESTAMP) - Data de criação
  - updated_at (TIMESTAMP) - Data de última atualização

Índices:
  - idx_estado - Índice na coluna estado
  - idx_data_reserva - Índice na coluna data_reserva
  - idx_mesa_id - Índice na coluna mesa_id
  - idx_token - Índice na coluna token_confirmacao

Constraints:
  - chk_numero_pessoas - Verifica se número_pessoas está entre 1 e 20

Relacionamentos:
  - Foreign Key: mesa_id -> mesas.id (ON DELETE SET NULL)
  - Referenciada por: reserva_observacoes.reserva_id

================================================================================
6. RESERVA_OBSERVACOES
================================================================================
Descrição: Armazena as observações/mensagens das reservas (comunicação entre
           cliente e restaurante).

Campos:
  - id (VARCHAR(36)) - Identificador único (UUID)
  - reserva_id (VARCHAR(36)) - ID da reserva
  - mensagem (TEXT) - Texto da observação
  - autor (ENUM) - Autor: 'cliente' ou 'admin'
  - autor_nome (VARCHAR(255)) - Nome do autor (opcional)
  - created_at (TIMESTAMP) - Data de criação

Índices:
  - idx_reserva_id - Índice na coluna reserva_id

Relacionamentos:
  - Foreign Key: reserva_id -> reservas.id (ON DELETE CASCADE)

================================================================================
7. PEDIDOS
================================================================================
Descrição: Armazena as comandas/pedidos do restaurante.

Campos:
  - id (VARCHAR(36)) - Identificador único (UUID)
  - nome_cliente (VARCHAR(255)) - Nome do cliente
  - mesa_id (VARCHAR(36)) - ID da mesa (pode ser NULL)
  - subtotal (DECIMAL(10,2)) - Subtotal dos itens
  - taxa (DECIMAL(10,2)) - Taxa adicional (atualmente 0)
  - total (DECIMAL(10,2)) - Total do pedido
  - forma_pagamento (VARCHAR(100)) - Forma de pagamento
  - observacoes (TEXT) - Observações gerais
  - observacoes_finalizacao (TEXT) - Observações na finalização
  - status (ENUM) - Status: 'aberta', 'pendente', 'finalizada'
  - data (DATE) - Data do pedido
  - hora (TIME) - Hora do pedido
  - created_at (TIMESTAMP) - Data de criação
  - updated_at (TIMESTAMP) - Data de última atualização

Índices:
  - idx_status - Índice na coluna status
  - idx_mesa_id - Índice na coluna mesa_id
  - idx_data - Índice na coluna data

Relacionamentos:
  - Foreign Key: mesa_id -> mesas.id (ON DELETE SET NULL)
  - Referenciada por: pedido_itens.pedido_id

================================================================================
8. PEDIDO_ITENS
================================================================================
Descrição: Armazena os itens de cada pedido/comanda.

Campos:
  - id (VARCHAR(36)) - Identificador único (UUID)
  - pedido_id (VARCHAR(36)) - ID do pedido
  - menu_item_id (VARCHAR(36)) - ID do item do menu
  - nome (VARCHAR(255)) - Nome do item
  - preco (DECIMAL(10,2)) - Preço unitário
  - quantidade (INT) - Quantidade (padrão: 1)
  - observacoes (TEXT) - Observações específicas do item
  - created_at (TIMESTAMP) - Data de criação

Índices:
  - idx_pedido_id - Índice na coluna pedido_id

Relacionamentos:
  - Foreign Key: pedido_id -> pedidos.id (ON DELETE CASCADE)

================================================================================
9. USUARIOS
================================================================================
Descrição: Armazena os usuários do sistema (administradores e atualizadores).

Campos:
  - id (VARCHAR(36)) - Identificador único (UUID)
  - email (VARCHAR(255)) - Email do usuário (único)
  - password (VARCHAR(255)) - Senha (em produção deve ser hash)
  - role (ENUM) - Papel: 'admin' ou 'atualizador'
  - active (TINYINT(1)) - Se está ativo (0 ou 1)
  - created_at (TIMESTAMP) - Data de criação
  - updated_at (TIMESTAMP) - Data de última atualização

Índices:
  - idx_email - Índice na coluna email
  - idx_role - Índice na coluna role

Relacionamentos: Nenhum

================================================================================
                    RESUMO DAS TABELAS
================================================================================

Total de tabelas: 9

1.  configuracoes          - Configurações do restaurante
2.  menu_secoes            - Seções do menu
3.  ementa                 - Itens do menu (pratos)
4.  mesas                  - Mesas do restaurante
5.  reservas               - Reservas de clientes
6.  reserva_observacoes    - Observações das reservas
7.  pedidos                - Comandas/pedidos
8.  pedido_itens           - Itens de cada pedido
9.  usuarios               - Usuários do sistema

================================================================================
                    RELACIONAMENTOS ENTRE TABELAS
================================================================================

MESAS (1) -> (N) RESERVAS
  - Uma mesa pode ter várias reservas
  - reservas.mesa_id -> mesas.id

MESAS (1) -> (N) PEDIDOS
  - Uma mesa pode ter vários pedidos
  - pedidos.mesa_id -> mesas.id

RESERVAS (1) -> (N) RESERVA_OBSERVACOES
  - Uma reserva pode ter várias observações
  - reserva_observacoes.reserva_id -> reservas.id

PEDIDOS (1) -> (N) PEDIDO_ITENS
  - Um pedido pode ter vários itens
  - pedido_itens.pedido_id -> pedidos.id

================================================================================
                    OBSERVAÇÕES IMPORTANTES
================================================================================

1. Todos os IDs são VARCHAR(36) e usam UUID() para geração
2. Booleanos são representados como TINYINT(1) (0 = false, 1 = true)
3. Timestamps usam CURRENT_TIMESTAMP para created_at
4. updated_at é atualizado automaticamente com ON UPDATE CURRENT_TIMESTAMP
5. Foreign Keys usam ON DELETE CASCADE ou ON DELETE SET NULL conforme necessário
6. A tabela ementa não tem FK para menu_secoes (secao é texto)
7. Em produção, a senha em usuarios deve ser hash (bcrypt)
